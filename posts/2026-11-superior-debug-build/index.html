superior: a build that kept its debug info

Notes on the superior IoT/Android bot, adding to eFeSpain's reporting: a DWARF build, a bricker module and an install-telemetry server.

Contents

  • Known vs. added
  • The debug build
  • Telemetry

superior is a musl C bot for routers, DVRs and Android TV boxes. eFeSpain reported it first and in depth, including the telnet /s dropper: Superior series, chapters 35–37. Read those first. This post covers only what my captures add. Static analysis only.

The debug build

superior.arm7, 672 KB, static, armv5te, musl cross-gcc 11.2.1. The DWARF names its source files:

The help text lists 36 attack methods; eFeSpain counts 37. kimwolf.c fits their finding that one method is named after Kimwolf. The CNC uses x25519 + ChaCha20 with a static server key (CNC_STATIC_PUB). I haven’t reversed the handshake yet.

Telemetry

The dropper reports each install step to a second host:

hxxp://195.178.110[.]91:18081/s/arch-<arch>
hxxp://195.178.110[.]91:18081/s/fetched-<arch>
hxxp://195.178.110[.]91:18081/s/launch-<arch>-<nc-ok|nc-blocked|nc-absent>-<path>

The launch string records whether the CNC port was reachable and where the binary landed, so the operator can presumably count failed installs per architecture.
